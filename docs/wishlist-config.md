# Local Wishlist configurations

wishport reads existing Wishlist OpenSSH files and original Wishlist YAML. An explicit Wishlist path may identify a file or a directory containing `config.yaml`, `config.yml`, or `config` (in that order). Automatic lookup checks `.wishlist` in the working directory, then `$XDG_CONFIG_HOME/wishlist.yaml`, `wishlist.yml`, and `wishlist` (default directory `~/.config`), then the same names in the operating system configuration directory. Absent automatic files are optional; absent explicit paths produce an error. Files are limited to 1 MiB and one YAML document; unknown and duplicate fields are rejected.

YAML supports `endpoints` with `name`, `address` (`host:port`, or `[IPv6]:port`), `user`, `description`, `link: {name, url}`, `forward_agent`, `request_tty`, `remote_command`, `proxy_jump`, `send_env`, `set_env`, `preferred_authentications`, `identity_files`, and duration `connect_timeout` (for example `10s`). Each endpoint retains its own identity, including repeated names. Invalid endpoint errors identify the endpoint number without echoing its contents.

Commands use the installed OpenSSH executable and argument arrays. OpenSSH files retain `-F` and their original alias, preserving Include and all native settings. YAML options are translated to explicit OpenSSH options, including multiple identity files. A shell session requests a TTY by default; a remote command does not. An explicit `request_tty` overrides that default. Connect timeouts round up to whole seconds. `LC_*` and `LANG` are sent by default. `set_env` entries must have portable variable names; control characters and `${...}` expansion syntax in values are rejected; literal percent signs are escaped. Values containing spaces are quoted for OpenSSH's option parser.

Only use trusted local Wishlist YAML: **`remote_command` intentionally runs as a command in the remote account's shell**. It never invokes a local shell. Remote commands cannot be combined with wishport's directory option. Identity paths may use `~` but cannot contain OpenSSH expansion tokens. ProxyJump accepts comma-separated aliases or `[user@]host[:port]`, with bracketed IPv6 when a port is supplied.

Top-level `hints` match discovered endpoint names using Wishlist globs (`*`, `?`, character classes, brace alternatives). Matching hints apply in order; later supplied scalar fields win; send_env, set_env, preferred_authentications, and identity_files append in order. They support the endpoint options plus `match` and `port`. Hints apply to Tailscale, mDNS, and DNS SRV discoveries, preserving their IDs and sources. They never change Forge or manually configured targets. Discovery data cannot supply commands or other SSH options; only the local hints do so.

Wishlist's `listen`, `port`, `users`, and `metrics` fields are accepted for compatibility and ignored when importing connections. Reading a file never starts an SSH server, loads external key files, or enables metrics. wishport serving uses its own explicit serve options; `--authorized-users PATH` explicitly loads the same YAML users section for hosted authentication. No Wishlist files are rewritten.

OpenSSH-format Wishlist files also apply to discovered names through native `-F` configuration, including Host wildcard rules. The original discovered address is pinned with `HostName` and hostname canonicalization disabled. Explicit discovered ports and users remain command-line overrides, so Host rules cannot replace a nonempty discovered user or port. Other native SSH options remain available. This preserves discovery destinations while avoiding a second, incomplete implementation of OpenSSH configuration precedence.
